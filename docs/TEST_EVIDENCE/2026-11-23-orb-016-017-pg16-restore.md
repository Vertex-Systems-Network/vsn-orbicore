## Observed assertions

1. Synthesized two tenant records, non-authenticating placeholder users, two mock hosting accounts, one mock website, one queued/completed-style job and one redacted synthetic audit record in the disposable PostgreSQL 16 service. No real passwords, contact information, live sessions, MFA keys, provider credentials, or customer data.
2. `pg_dump --format=custom` produced an actual whole-fixture database archive, and `pg_restore --single-transaction --exit-on-error --no-owner --no-acl` restored it into a **new named database** on the same disposable PostgreSQL 16 server. The client was run from the pinned `postgres:16-alpine` image because the GitHub runner default client did not match PG16. This is not a different host or region.
3. Postrestore normalized row checksums matched source for synthetic users, accounts, websites, jobs and audit rows. Row counts, the restored sessions/passkeys/authenticator/recovery/outbox table structures and PostgreSQL user table RLS flag were verified.
4. An attempted cross-tenant `sessions` insert in the RESTORED database was rejected by the composite foreign key. A deliberately damaged custom archive failed `pg_restore --list`. A target-only health-state mutation was detected as mismatch; blind re-import to the populated restored database was rejected.
5. No production login, real app Postgres cutover or new live service was enabled; default HTTP still uses SQLite.

## Limitations and blockers

- **Not off-host disaster recovery:** Both source and restored PostgreSQL databases reside on the **same ephemeral CI PostgreSQL service**. No storage account, separate cluster/global roles, external vault, runtime secret custody, real encrypted MFA/passkey keys, Redis job queue or full SQLite v7 source was restored.
- `--no-owner --no-acl` intentionally skips owners and grants. PostgreSQL RLS metadata survived, but **source role grants, real runtime authorization and new-cluster IAM parity are not proven**. SQL-file migrations still lack a durable migration ledger tested in this drill. No point-in-time WAL restore, true backup retention, host power-loss simulation, restore SLO/RTO or rollback of an application upgrade was tested.
- The archive is a disposable generated CI file and is intentionally not attached. Do not infer production readiness, full secure backup completeness, zero downtime or approval for an authentication authority change.
- ORB-016 and ORB-017 remain `testing / integration_tested` and ORB-005 stays `in_progress`. Required next: independently stored encrypted backup with verified key-restore capability, PostgreSQL cluster roles and RLS/GRANT parity, real job/secret/MFA restore, migration ledger and operator-authorized rehearsal on a separate deployment.
- Evidence/documentation follows tested functional SHA; final docs-head and postmerge `main` checks must be verified independently.
