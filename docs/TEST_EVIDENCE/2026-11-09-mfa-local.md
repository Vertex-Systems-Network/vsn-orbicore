## Limits / gates

- TOTP is a compatibility fallback and is not phishing-resistant. WebAuthn/passkey registration, assertion verification, credential counter/replay handling, and browser interaction are not implemented.
- Recovery code use consumes the code, revokes prior sessions, audits the event, and creates an outbox row. That row remains `blocked_unverified_contact`: no verified notification-address workflow or delivery provider exists, so no message is claimed as sent. Authenticator rebinding/recovery and safe code replacement are not implemented.
- AES-256-GCM requires a separately supplied base64 32-byte `ORBICORE_MFA_ENCRYPTION_KEY`. This repo does not provide a production secret manager, key rotation, or recovery/backup procedure. Loss of the key makes saved TOTP seeds unreadable.
- Do not use for provider credentials or expose as production auth until remaining security gates pass.
