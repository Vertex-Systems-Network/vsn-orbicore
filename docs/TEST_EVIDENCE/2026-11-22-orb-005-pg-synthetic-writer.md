## Scope delivered and tested

1. **No-login, non-bypass restricted capability:** `db/migrations/006_postgres_synthetic_write_gateway.sql` creates `orbicore_synthetic_submitter NOLOGIN NOINHERIT NOBYPASSRLS`; explicitly revokes direct table access and PUBLIC function execution; grants that role **EXECUTE only** on `public.orbicore_submit_synthetic_inventory`. Function uses `SECURITY DEFINER`, a pinned safe PostgreSQL search path and qualified tables; schema-owner control is required.
2. **Real restricted LOGIN proof (CI only):** the test creates an ephemeral `orbicore_ci_gateway_login LOGIN NOINHERIT NOBYPASSRLS` with a random password generated only in runner memory. Grants explicit **SET TRUE / INHERIT FALSE** membership to the NOLOGIN submitter role. Direct login queries for job tables and direct invocation of the protected function fail with SQLSTATE 42501; a scoped transaction `SET LOCAL ROLE orbicore_synthetic_submitter` successfully calls the protected function. The ephemeral password is not written to source, logs, artifacts or project config.
3. **PostgreSQL actor/tenant revalidation:** function takes only SHA-256 session token hash, organization ID, mock account ID and idempotency key as parameters, never user role/actor from caller. Reads PostgreSQL sessions, users and accounts; rechecks token expiry, tenant equality, disabled state, owner/admin/operator role, MFA verification and **`source='mock_fixture'`**. Locks related session, actor and account rows **FOR SHARE** through the transaction to serialize against revalidation changes. Viewer, disabled, expired, missing/MFA-unverified, cross-tenant and provider-account submissions fail closed. A caller-set `orbicore.tenant_id` GUC cannot authorize a different tenant; the function ignores it.
4. **Single transaction with durable synthetic work, signal and audit:** the narrow Node wrapper in `apps/api/postgres-synthetic-gateway.mjs` begins one PG transaction, switches to the restricted role, calls one parameterized SQL function, commits only on a validated success result and rolls back on every exception. The function creates only a fixed `inventory_refresh` synthetic job, its sole `job_outbox` event and a `job.enqueue` audit entry; a deliberate CHECK failure on the **last audit statement** proves the job and outbox are rolled back. No Redis notification is published before transaction commit.
5. **Reproducible idempotency:** PostgreSQL computes the existing Node canonical SHA-256 of tenant bytes + NUL byte + idempotency-key bytes (using the built-in PostgreSQL 16 SHA-256 bytea function). Exact duplicates return the same job without generating extra outbox/audit; account/actor key reuse conflicts. Two concurrent requests for the same key yield precisely one creator and one duplicate. The same literal key is independently scoped across two tenants.
6. **Tamper-evident audit compatibility for this fixed event:** migration adds a monotonic PostgreSQL `audit_sequence` identity to avoid timestamp tie ambiguity; the function locks a tenant-specific advisory key during audit append. The audit's raw JSON text and ISO UTC-millisecond timestamp enter an ordered string-array hash matching the existing Node `computeAuditEntryHash`; hosted tests recompute and compare every newly created PostgreSQL audit event. The test also verifies the new event links to a pre-seeded SHA-256 legacy-compatible audit head.
7. **Revocation and role isolation:** deleting a PostgreSQL session or disabling a user prevents even replaying a previously-used idempotency key. Direct attempts to SELECT credential hashes or secret-reference ciphertext, INSERT audit/outbox or UPDATE/DELETE job/user rows while in the restricted role are denied, and the read-only tenant role cannot invoke the writer.

## Explicit limits and remaining production gates

- **Only synthetic inventory-refresh job submission is covered.** The normal application HTTP API/auth/session/MFA/audit writes still use SQLite. This PR does **not** implement HTTP cutover, multi-operation PostgreSQL writes, a deployable application DB login, real tenant membership provisioning, production credential custody, provider APIs or live cPanel/WHM actions.
- The ephemeral non-superuser LOGIN proves the DB privilege pattern on real PostgreSQL 16. **Production deployment role creation, isolation, rotation, connection pool topology, TLS, least-privilege network access and revocation operations are not validated.** A future production app connection must not use the schema owner/superuser.
- The audit-chain parity proof covers the function's **fixed ASCII-only event schema**, not arbitrary multilingual JSON or imported chains from a legacy SQLite dataset. Migration 006 assigns `audit_sequence` to existing PG rows, but preexisting cross-store chain ordering and concurrent audit writers **outside this guarded function** have not been proven. Full PostgreSQL-only unified audit migration, WORM/off-host archiving and replay/restore testing are still open.
- The function refuses a legacy unchained audit head and uses fixed `mock_fixture` data; no authorization for external provider actions can be inferred. Existing PostgreSQL schema-owner write paths can still bypass this separate gateway; not all runtime writes are protected.
- Job lease/worker processing remains an opt-in synthetic Redis runner. Full SQLite v7 job-history/secret-reference migration, complete controlled application cutover/rollback, off-host recovery, physical authenticator tests and live provider authorization remain outstanding.
- Task lifecycle remains **ORB-005 `in_progress/integration_tested`**, ORB-004/016 **`testing/integration_tested`**.
