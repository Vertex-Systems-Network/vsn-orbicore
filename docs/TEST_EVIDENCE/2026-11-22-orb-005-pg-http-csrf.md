## Verified bounded implementation

1. **PostgreSQL-only session authorization:** migration `007_postgres_http_session_probe.sql` adds an explicitly granted SECURITY DEFINER probe; public EXECUTE is revoked. It returns a scoped organization ID, not passwords or session details, only for a valid PostgreSQL SHA-256 session hash with unexpired session, enabled owner/admin/operator and completed MFA when required. This neither consults SQLite nor trusts a custom tenant GUC.
2. **Actual least-privileged database login:** hosted tests use a real disposable PostgreSQL `LOGIN NOINHERIT NOBYPASSRLS` with random password generated only in runner memory. The login has no direct users/sessions table or protected-function privilege; its role-scoped transaction can execute the NOLOGIN submitter role's probe and authenticated synthetic writer. Credentials are absent from the committed repo and evidence.
3. **CI-only HTTP boundary:** `apps/api/postgres-synthetic-http-harness.mjs` is explicitly gated by `GITHUB_ACTIONS=true` and `ORBICORE_CI_SYNTHETIC_PG_HTTP=1`, listens on `127.0.0.1` with an ephemeral port, and is **not imported by the production `createApp` server**. It exposes only `GET /__ci/pg/session/csrf` and `POST /__ci/pg/jobs/refresh`. The test provides an opaque fixture cookie; the harness hashes it before the PostgreSQL probe.
4. **CSRF/HTTP protections:** the GET endpoint returns a process-secret HMAC CSRF token only after PostgreSQL session validation, with no-store security headers. The mutation requires the original loopback `Origin`, valid `Host`, non-cross-site `Sec-Fetch-Site`, valid signed CSRF header, `application/json`, a bounded body and a fixed single `accountId` field. Client-supplied organization IDs are rejected. Malformed JSON, oversized payloads and missing idempotency keys are rejected.
5. **Strict tenant, role and MFA policy:** anonymous, viewer, disabled, expired and MFA-unverified sessions cannot obtain a valid submission. Cross-tenant and provider-account submissions are refused by the PostgreSQL writer. Duplicate idempotency keys return the same job, and conflicting accounts return HTTP 409. Only `mock_fixture` inventory refresh is allowed.
6. **Fresh revocation proof:** deleting an existing PostgreSQL session, or disabling its actor, rejects a later request even if the browser previously obtained a CSRF token. In a separate controlled race fixture, the session is revoked **between the HTTP probe and the writer**; the PostgreSQL submission function checks again and denies the transaction, leaving job counts unchanged.
7. **Single-store atomic audit/outbox proof:** the HTTP-created jobs, outbox events and SHA-256 audit records exist in PostgreSQL only and match Node's existing audit-hash algorithm. A deliberately failing final audit insert yields a sanitized HTTP 503 with **no job or outbox rows committed**. Raw SQL errors and internal database diagnostics are not included in HTTP responses.
8. **Raw HTTP host testing:** initial tests mistakenly relied on Node `fetch` to send a forged `Host` header; that client normalized it and caused false expectations (first standard/service runs failed). Replaced with actual `node:http.request` raw host header requests and verified the host-denial behavior on the first fully green head. This was a test-harness issue, not a bypass finding.

## Explicit limits and blockers

- **Not a production HTTP or SQLite→PostgreSQL cutover.** Normal `apps/api/server.mjs` routes still authenticate through SQLite; the synthetic HTTP harness is a separate loopback CI fixture and does not issue real login cookies, run a login workflow or load real identity credentials. A test client injects an opaque session cookie matching a seeded PostgreSQL hash.
- **Not a production CSRF lifecycle.** HMAC CSRF issuance is process-local and tied to synthetic test sessions; production browser cookie attributes, revocation on key rotation, origin validation behind TLS/reverse proxies, distributed throttling and session MFA challenge/recovery flows need independent integration testing.
- **No provider actions.** Every job remains fake `mock_fixture`; no live cPanel/WHM, provider token, notification delivery, secret-reference decryption or account modification. No authority switch for existing Redis worker or default API.
- Restricted role and PostgreSQL function prove a narrow boundary, not all runtime writes, imported audit ordering or production DB login/rotation policy. Full SQLite v7 migration of jobs, historical audits, secret references/key provenance and reversible authority cutover remains open; off-host restore and failure scenarios are not proven here.
- ORB-005 lifecycle remains `in_progress / integration_tested`; ORB-004/016 `testing / integration_tested`.
