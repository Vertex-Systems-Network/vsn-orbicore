# ORB-006/010 — cPanel credentialed URL host/port authority

**Date:** 2026-11-23 UTC. **Status:** Regression code committed to feature branch; hosted PR CI unverified at documentation write. All test inputs synthetic; no cPanel token, network call, DNS resolution or live provider access.

## Threat and remediation

The existing outbound guard checked the URL generated by interpolating a caller-supplied `connectionRef.host` into `https://${host}:2083`. For inputs such as `cp.example.org/path`, the `:2083` suffix became part of the *path*, not a port. `URL.origin` then silently became `https://cp.example.org` (HTTPS 443). A subsequently credentialed GET could hit the wrong service port with the cPanel Authorization header, despite the URL passing the public-host SSRF check. The synthetic-account and boundary-probe routes also accepted URL-shaped host data without enforcing the bare-host contract.

The new `validateCpanelApiHost` requires a bare hostname, IPv4 literal or bracketed public IPv6 literal (Unicode DNS names are allowed for canonical IDNA handling). It rejects schemes, embedded credentials, ports, paths, queries, fragments, escape bytes and surrounding whitespace, then checks the shared private/loopback host guard. The returned origin must explicitly retain HTTPS port 2083. `LiveCpanelAdapterBoundary` and both API routes use this single check. Public DNS names normalize to canonical hostname; no redirect following is enabled.

## Regression plan and evidence scope

- Pure-host matrix: reject 17 URL-shaped/ambiguous host strings and six private/metadata/loopback strings; allow four public forms with fixed 2083 authority.
- Fake authorized transport: assert eight rejected hosts cause **zero** `fetchImpl` invocations; one public hostname sends exactly `https://cp.example.org:2083/execute/DomainInfo/domains_data` and `redirect:manual` without exposing token in response.
- Local SQLite/HTTP integration: owner bootstrap, 4 synthetic-account rejects, 4 no-network cPanel boundary-probe rejects, no unauthorized account creation, canonical public host accepted, probe reports `liveConnections:0`.
- Verification pending GitHub Actions at time of evidence-plan creation. PR must pass hosted standard CI, task ledger and applicable browser jobs before merge; service workflow is path-scoped and may not be triggered.

## Honest limits

This closes one string-to-URL authority ambiguity. It does **not** implement DNS resolution and connection peer pinning, DNS-rebinding protection, live provider UAPI compatibility, authorized sandbox token provisioning, production identity cutover, external KMS or offsite restore. ORB-006 remains `blocked/none`; ORB-010 remains `in_progress/unit`.
