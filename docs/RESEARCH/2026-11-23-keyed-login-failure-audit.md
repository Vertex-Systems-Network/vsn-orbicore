# ORB-005 — CI-only keyed login-failure audit privacy

**Research date:** 2026-11-23.

The [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) requires generic login failure responses independent of whether a supplied account exists. The [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) recommends recording authentication failures without persisting passwords, secrets or unnecessary directly identifying material. The [OWASP Credential Stuffing Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Credential_Stuffing_Prevention_Cheat_Sheet.html) recommends multiple coordinated throttling signals; a single account counter is insufficient against spray and distributed attacks. Node's [crypto HMAC documentation](https://nodejs.org/api/crypto.html#cryptocreatehmacalgorithm-key-options) defines `createHmac`.

A new **CI-only** reject-audit contract uses `HMAC-SHA256("orbicore:ci:login-failure:v1\\0" || canonical_identifier)`, with a separately generated 256-bit minimum in-memory key and `key_id`. The persistence schema stores only keyed digest, non-secret key ID, random event ID, timestamp, and generic reject outcome. It intentionally has **no tenant, user ID, account existence, raw email, source IP, submitted password or recovery code** columns. The same contract records both unknown-account and known-account/wrong-password rejected synthetic attempts. Key rotation requires retaining old active keys for the live rate-limit window, otherwise **fails closed**, not silently reset. Tests cannot prove side-channel timing indistinguishability of ordinary HTTP: no production handler uses this module.

Unresolved: independently protected key custody/rotation, rate-limiting at edge/IP/device/global scope, bogus-email bounded-cost strategy, actual HTTP login integration, retained audit immutability/retention, user privacy/erasure and opt-in logging policy, distributed quota consistency, privacy-preserving SOC alerting, and explicit production approval. No real email, password or tenant is processed by this synthetic proof.
