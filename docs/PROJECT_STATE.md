**ORB-004/005 cross-connection persisted SQLite CI recovery-hold DML guards (PR CI pending):** Prior SQLite `TEMP` BEFORE INSERT/UPDATE/DELETE triggers protected only the running application's connection. Replaced them with **main-schema durable triggers** for every ordinary source table, installed within the atomic initialization writer transaction, checking the committed source recovery marker on **any SQLite connection** that respects the database triggers. Trigger names derive from hexadecimal UTF-8 table names instead of sorted indices, so upgrades cannot silently leave formerly guarded tables unprotected. The installer rejects mismatched existing trigger definitions instead of blindly accepting a name collision. File-backed regressions check cross-connection post-app-close denial and stable trigger names when an earlier-alphabetized table is added; prior direct app DML tests updated to expect independent connection denial. [Evidence plan](TEST_EVIDENCE/2026-11-23-orb-004-persisted-cross-connection-source-guards.md). This modifies SQLite main schema but not `schema_migrations` version, and does **not** block DDL/DROP TRIGGER, elevated direct file writes, later-added uninstrumented tables, PostgreSQL/Redis, cross-store identity migration or real providers.
